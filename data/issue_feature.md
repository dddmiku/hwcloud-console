# 建议为任务查询接口增加按完成状态过滤的参数

## 背景

目前调用任务列表接口时，需要拉取全部任务后在前端自行按 `is_finish` 过滤。当任务数量较多、分页较多时，会带来不必要的请求量和解析开销。

## 期望功能

希望 `query-mission-list-by-condition` 接口支持一个可选的完成状态过滤字段，例如：

```json
{
  "page_no": 1,
  "page_size": 100,
  "category_key": "DAILY_MISSIONS",
  "is_finish": 0
}
```

传入后服务端只返回未完成的任务，`total` 同步反映过滤后的数量。

## 使用场景

- 自动化脚本只需要知道"还有哪些任务没做"，不需要已完成的记录
- 任务列表页的"待完成"标签页可以直接请求服务端，而不是全量拉取后本地过滤

## 补充说明

如果担心影响存量调用方，可以把该字段设计为可选，不传时保持现有行为。这样对现有集成完全兼容。
